## 真实宿主只读预检

在授权的现有 KVM 宿主临时目录运行新 Agent `preflight`，没有启动正常任务 worker、注册新 Agent、替换当前配置，也没有创建/关闭/删除虚拟机。

- 探测前后均为 20 个域，能够区分外部域与平台托管域；网桥、libvirt 与 QEMU 读取正常。
- 测试预算固定为 2 CPU / 2048 MiB / 20 GiB，同时上报独立实时余量，未把当前剩余量当预算总量。
- 默认工具路径缺少 `arping` 和 `cloud-localds`，预检正确显示 `DEGRADED`。不能把该结果当作已具备新版写模式条件；升级前须由运维安装依赖或配置受控可执行路径，并重新预检。
- 没有目录 catalog 的单独预检 `readiness_complete=false` 是预期行为；上线后仍需完整镜像/网络心跳与管理员手动放开调度。
- 临时测试二进制及目录已清理，现有运行 Agent、虚拟机和磁盘没有变动。

本轮不是新版本在真实 KVM 上的完整创建、远程 OSS、开关机、删除硬件端到端验收。尤其现场 ARP 权限、宿主 DNS/TLS、Guest Agent、ARM Guest 镜像和控制台网络还需在隔离宿主上执行部署指南的最小测试流程；不得以模拟执行器或本机 TLS 测试宣称这些现场条件已通过。

## 版本与默认行为

- 配套版本均为 `0.5.0`，固定版本镜像为 `lixiaokun/vmp-backend:0.5.0`、`lixiaokun/vmp-frontend:0.5.0`；生产不建议仅依赖可变的 `latest`。
- 新协议未就绪、库存过期、镜像/网桥缺失时拒绝新申请；升级窗口应暂停调度，确认完整心跳后再恢复。
- 自动续期默认关闭，用户额度默认不限，历史默认永久保留，群通知整体默认关闭。新增治理能力不会自动修改既有用户的授权或删历史记录。
- 单次超过 168 小时仍审批；保留期仍保留完整平台预算，磁盘/IP 不提前回收；恢复最多一次。
- 本轮发布代码与产物，不自动升级现有控制面或 KVM 宿主。上线前备份数据库、加密密钥、Agent 私有状态与受控实例数据。
