# 0.5.5 实例详情修复与升级

配套：后端 **0.5.5**、前端 **0.5.3**、Agent **0.5.4**。发布日期：2026-10-10。

## 修复内容

0.5.4 增加实例关联的 IP 复核任务历史时，查询把同一个参数作为 `uuid` 和 JSON 提取的 `text` 比较，PostgreSQL 在解析时返回 `operator does not exist: text = uuid (SQLSTATE 42883)`。即使该实例没有探测任务，详情也会返回 HTTP 500；前端将其显示成“加载失败 / 服务异常”。

0.5.5 明确转换 UUID 的规范化文本用于历史关联，保留 CREATE 和关联 PROBE 任务。前端页面和 Agent 协议没有变化，不删除历史数据，不修改虚机、IP、配额、租期或数据库表结构。

## 已经部署 0.5.4：只更新后端

1. 按原备份流程备份数据库和部署配置，安排短维护窗口，避免用户同时提交新操作。
2. 在原 `.env` 或实际生效的部署清单中仅修改后端镜像：

```dotenv
VMP_BACKEND_IMAGE=lixiaokun/vmp-backend:0.5.5
```

3. 使用原来的项目名、Compose 文件及覆盖参数拉取、更新 **control-plane**。下面仅为内置数据库 Compose 的示例；外置数据库使用自己原来的 `compose.external-db.yaml`，不能改成新项目：

```bash
docker compose --env-file .env -f compose.yaml pull control-plane
docker compose --env-file .env -f compose.yaml up -d --no-deps control-plane
docker compose --env-file .env -f compose.yaml ps
docker compose --env-file .env -f compose.yaml logs --tail=80 control-plane
```

4. 后端健康后，浏览器刷新，再从“我的虚拟机 / 全部实例”进入详情。核对实例配置、任务历史及审计均显示；不要用重新申请虚机来解决详情报错。

本次不需要：

- 更新前端或 Agent；
- 新环境变量、签发宿主凭据或重新生成密钥；
- 手工运行 SQL、重建 PostgreSQL 或清空数据卷；
- 重启宿主、重新创建虚机、调整网络或解除 IP 绑定。

最高迁移仍为 021 / 共 21 条，已执行迁移不改写。后端启动仍检查既有迁移台账。不要运行 `docker compose down -v`。

若使用 Kubernetes 或其他部署方式，仅在原后端工作负载中替换这个固定镜像，保留原环境变量、Secret、外置数据库和服务配置；等待新副本健康后再检验详情接口。不要将网站登录凭据当作服务器 SSH 或集群权限。

尚未完成 0.5.4 IP 探测 / 独立身份升级的旧环境，应先按 [旧版升级与隔离恢复](0.5.4升级与IP隔离恢复.md) 完成必要组件更新，不能仅换后端跳过协议升级。

## 验收范围与上线边界

发布前使用独立 PostgreSQL 的真实 HTTP 详情请求测试，不以模拟前端成功响应代替 SQL 验证。测试覆盖普通所有者 / 管理员访问、其他用户隔离、空历史数组、真实任务关联、无关任务排除、大写 UUID、秘密字段不返回和资源无变更。

完整数据库 race、静态检查、已知漏洞检查，以及现有前端与新后端的隔离浏览器详情流程为发布门禁。镜像发布后验证 Linux amd64 / arm64 清单，不覆盖旧固定版本。

本次已实际执行：修补前新详情 HTTP 用例返回 500，修补后该用例连续 20 轮 race 通过；最终冻结后的全量数据库回归重复两轮通过，vet / govulncheck v1.8.0 通过。原前端 59 项回归仍通过。在现有前端连接新后端和独立数据库的浏览器验收中，“全部实例 → 详情”得到真实 HTTP 200，并显示 CREATE / 关联 PROBE 和审计；不是用模拟成功 JSON 替代数据库查询。测试数据与 Agent 现场均和生产隔离，不执行真实虚机写操作。

174 环境在修复前的只读核查已复现：健康 / 列表 HTTP 200，详情 HTTP 500 / 42883。本次发布不自动更新 174 或任何宿主，不把隔离验收描述成生产已升级。升级后请在自己的环境再次核对。
