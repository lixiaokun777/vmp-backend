# 0.6.0 发布与升级

发布日期：2026-10-12。配套版本：后端 `0.6.0`、前端 `0.6.0`、Agent `0.6.0`。

## 本版内容

- 普通用户登录后进入“我的概览”，查看在用实例、个人配额占用、最近到期和 24 小时到期风险。
- Agent 通过 libvirt `domstats` 采集平台托管运行域的 CPU 与内存基础指标；后端按分钟保存 7 天，实例详情展示最近 24 小时曲线。
- “我的申请”显示短租期自动交付记录，并把结构化任务错误翻译为中文原因和下一步建议。
- 数据按当前登录用户隔离；管理员可以读取全部实例指标，普通用户只能读取自己的概览、申请和实例指标。

## 升级前

1. 备份 PostgreSQL、原 Compose / `.env`、反向代理配置、每台 Agent 的完整状态目录和配置文件。
2. 确认当前宿主心跳正常，没有正在执行的创建、删除、镜像同步或密码重置任务。
3. 保留 `SETTINGS_ENCRYPTION_KEY`、`CONSOLE_SIGNING_KEY`、数据库连接、Agent 宿主 UUID 与独立运行凭据原值。

## 升级控制节点

将镜像固定为：

```dotenv
VMP_BACKEND_IMAGE=lixiaokun/vmp-backend:0.6.0
VMP_FRONTEND_IMAGE=lixiaokun/vmp-frontend:0.6.0
```

在原 Compose 项目和原环境文件下执行：

```bash
docker compose --env-file .env pull control-plane web
docker compose --env-file .env up -d --no-deps control-plane
docker compose --env-file .env logs --tail=200 control-plane
curl -f http://127.0.0.1:8080/api/v1/health
docker compose --env-file .env up -d --no-deps web
```

后端启动时自动执行 `022_instance_metrics.sql`。外置数据库同样不手工挂载或执行 SQL；数据库账号需要建表、索引和写迁移台账权限。迁移失败时控制面拒绝提供服务，应先恢复旧镜像并排查权限，不能删除迁移台账绕过。

## 升级 Agent

从 [Agent 0.6.0 Release](https://github.com/lixiaokun777/vmp-agent/releases/tag/v0.6.0) 下载与宿主架构匹配的安装包和 `SHA256SUMS`。逐台停止旧 Agent、备份安装目录，将新包解压到临时目录并保留原 `conf/agent.env`、状态目录和运行账号，然后执行预检并启动。

本版没有新增必填 Agent 配置，不重新签发 `AGENT_HOST_ID` 或 `AGENT_RUNTIME_TOKEN`。新 Agent 的心跳字段向后兼容；旧 Agent 未升级时平台仍可管理实例，只会显示“等待 Agent 指标”。新建虚拟机 XML 会启用 virtio balloon 统计；既有虚拟机无法提供 guest unused 时，Agent 会回退到宿主 RSS，页面仍明确标记数据来源。

## 验证

1. 普通用户登录后首页显示“我的概览”，数据仅包含本人实例。
2. 打开运行中实例详情，连续收到至少两个 Agent 心跳后出现 CPU 曲线；内存曲线取决于 balloon 或 RSS 是否可用。
3. 用测试环境制造一次结构化交付失败，确认“我的申请”显示错误码、中文诊断和下一步建议。
4. 管理员确认宿主心跳、镜像/网络就绪、任务领取、VNC/串口和原有生命周期操作没有回归。

## 回滚

前端和 Agent 可以回滚到上一固定版本，但旧组件不会显示或上报监控指标。后端执行 022 后不要手工删除指标表或迁移记录；表对旧版本无业务依赖，可保留并回滚到原后端镜像。回滚不清空数据库、Agent 状态目录、实例磁盘或 IP 绑定。
