# 0.8.2 发布与升级

0.8.1 后端因 Go 标准库漏洞被门禁阻止，没有发布镜像；不覆盖已有标签，改发 0.8.2。构建工具链升级为 Go 1.27.4。

本次发布前后端镜像0.8.2，包含累计续期审批修复；Agent维持0.7.3，不重新发布安装包。发布流程保留数据库竞态、静态检查、漏洞扫描及双架构门禁，不覆盖旧固定版本，不自动升级服务器。

## 从0.8.0升级

1. 备份数据库和原部署配置，在维护窗口暂停新增申请/续期。
2. 在原`.env`或部署定义中把后端镜像改成`lixiaokun/vmp-backend:0.8.2`，前端改成`lixiaokun/vmp-frontend:0.8.2`。不要用示例配置覆盖自己的密钥、数据库地址或宿主凭据。
3. 先拉取并更新后端，确认健康后更新前端；继续使用原Compose项目或Kubernetes工作负载，不另建空平台。
4. 从0.8.0升级没有新增数据库迁移，最高仍为024，不需要导入SQL、新增环境变量或更换Agent。更早版本仍按 [0.8.0升级说明](0.8.0发布与升级.md) 完成原有迁移和独立身份要求。

Compose内置数据库示例（在原项目目录）：

```bash
docker compose --env-file .env -f deployments/compose/compose.yaml pull control-plane web
docker compose --env-file .env -f deployments/compose/compose.yaml up -d control-plane
docker compose --env-file .env -f deployments/compose/compose.yaml logs --tail=80 control-plane
docker compose --env-file .env -f deployments/compose/compose.yaml ps
# 确认后端健康后再更新网页。
docker compose --env-file .env -f deployments/compose/compose.yaml up -d web
```

外部数据库使用原`compose.external-db.yaml`，保留原DATABASE_URL。不要执行`down -v`或清理数据库、Agent状态和虚机磁盘。

## 行为变化与验收

续期后到期时间超过首次创建加168小时，哪怕本次只续1小时也须审批；恰好168小时仍可自动执行。有待处理续期审批时不能继续改到期时间，批准只授权本次延期；自动续期越界会暂停并提示手动申请。原到期时间不追溯缩短，创建与保留期恢复沿用既有规则。详情见 [累计续期审批](累计续期审批.md)。

审批保存申请时的基准和目标期限。管理员调整小时数按原基准执行，不从审批时重新累计；若期间到期时间被其他操作改动，则拒绝旧审批，需重新提交。短租期重提不能绕过累计判断。

本地专用PostgreSQL16全量竞态回归、go vet、前端71项测试通过，发布工作流再次验证后构建Linux amd64/arm64。隔离测试不是业务宿主实测；上线后用授权的测试实例检查边界、待审批不延期和自动续期暂停，不对业务实例做故障注入。
