# 0.5.0：P2 可靠性、功能补齐与治理

本版本必须使用配套后端、前端和 Agent，不把页面可保存字段等同于已完成交付。功能与测试索引如下；发布前实际验证记录由发布说明给出。

## 修复范围

| 项目 | 实现与边界 |
| --- | --- |
| LDAP 首配/登录来源/统计/校验 | 首配固定刷新 LDAP 页面；表单重置后来源与标签保持一致；规格以 ID/分配快照统计；所有创建入口使用同一验证函数。这四项继承 P1 修复并持续回归。 |
| 总预算与安全余量 | Agent 上报固定总预算与独立实时安全余量。预留只从预算扣一次，实时余量只作为新申请安全门，不再次扣减既有预留。 |
| 镜像路径与交付 | 受限根目录打开、受保护缓存与 backing 依赖，拒绝符号链接越界；远程下载显式受控、摘要/格式/大小校验、原子激活，不使用半成品。 |
| LDAP 与管理员 | 分页拉取完成才提交目录更新；平台停用与目录存在独立；管理员变更串行事务，始终保留本地应急管理员。 |
| 分页与交互 | 用户、实例、审批、IP 用服务端分页及完整状态筛选；局部更新和请求代际避免导航回跳/会话泄漏；操作有错误反馈和重复点击保护。 |
| IP 与交付 | ARP、Guest Agent、目标 MAC 和可用性分层，ping 只是证据之一；网络未就绪保留托管域现场，不凭 ping 超时单独删盘；失败重试重新建立缺失 IP 预留。 |
| 宿主对账 | 仅完整成功扫描中可信的托管域影响实例观察状态；单次缺失/失败不误删域、磁盘、IP 或账本，缺失连续确认后仍由管理员修复。 |
| 救援控制台 | 授权所有者/管理员对实际存在的托管域进行 VNC/串口诊断，创建中或错误状态不等于无救援；不允许接管外部 VM，不通过救援绕过租期或启动已释放域。 |
| 无障碍与凭据 | 通用弹窗语义、键盘焦点陷阱/恢复、表单关联和登录 Tab；未确认保存凭据时关闭/导航需明确确认，明文不持久化。 |

## 审批代理与转交

- 管理员可为自己设置其他有效管理员作为代理，时间区间不超过 90 天，禁止自代理和重叠的链式代理。
- 新长租期申请按有效管理员当前待审批量分配；代理期内转到代理人，期间已有待审批也刷新路由，到期返回原管理员。
- 任意有效管理员仍可应急处理，分配是协作路由而非新增角色；手工转交仅 pending、未过期的单据，必须说明原因并留下审计。
- 调整租期仍直接传到实例执行事务，重复批准不会生成第二台实例。

## 公平使用与自动续期

“超过 7 天”仍指单次申请/延长/恢复的小时数超过 168；不把现有连续短续期静默改判为需要审批。

管理员可设每用户实例数、CPU、内存 MiB、磁盘 GiB、未来剩余租期和从实例创建开始的总占用期限；0 表示不限。运行、停止、保留期和失败待清理实例均计入已用资源，防止反复释放/恢复规避额度。资源检查和预占同事务，用户级锁防并发超限。

保留期沿用当前完整资源预占策略：磁盘、IP、CPU 和内存预算在最终删除成功前都保留，避免恢复时重新争抢算力。这不等于关机 VM 仍实际消耗运行内存。代价是保留期占用平台预算；如需“只留盘/IP、恢复时重新申请 CPU/内存”，须另行设计恢复失败和资源排队，不在本版静默改变行为。

自动续期默认关闭；管理员开启后，用户仍需在自己的实例中主动授权每次小时数与次数。每次最多 168 小时，受平台小时/次数/未来期限/总占用上限共同约束。到期前一小时每分钟检查，成功次数持久化；反复开关不重置次数。账号失效、达到上限或配置关闭会停止并留下错误和审计，不绕过超过 7 天的审批。故障或超时已到期后不擅自恢复，仍走保留期恢复入口。

## 平台群事件

除租期提醒外，可单独开关审批提交、审批/交付失败和宿主异常/恢复提醒。只收集启用后的新审批，失败事件还限于最近 24 小时，防止重新开启后补发大量历史失败。宿主心跳超过 120 秒产生故障边沿；健康心跳不群发，不自动删除 VM。事件键与队列跨重启去重，失败退避重试最多 5 次，通知记录可查。

机器人不提供业务幂等确认，HTTP 成功后数据库提交失败等极端情况可能重复，属于至少一次交付，不能承诺绝对只发一次。群消息使用 Markdown、平台链接，不含密码、Agent 令牌、控制台票据或原始敏感错误内容；管理员登录后查看真实根因。

## 历史保留与归档

- 默认全部永久保留，无后台自动删除。
- 配置期限时审计至少 180 天、通知至少 30 天、审批至少 90 天；这只是产品保护下限，不代替组织自己的合规评审。
- 管理员生成有限批次压缩 NDJSON（最多 5000 行/32 MiB 原文）、下载后以 SHA-256 校验，再输入确认清理；只清理本次归档精确 ID、截止期以前的终态记录，归档后发生改动的行通过逐行摘要保护，须重新归档才能清理。
- 活跃审批/待发送通知不可清理。修改保留策略后清理会重新校验更严格截止期；旧归档不能绕过当前永久保留设置。
- 清理源记录不删归档；确认已备份后才可删除该归档数据。两种删除不可撤销，操作本身留审计。归档保存在 PostgreSQL，下载至组织档案存储后再清理服务器副本才会降低长期数据库占用。
- 不清理仍供资源、任务回执或安全锁使用的表；任务确认回执的 60 天窗口遵循原可靠执行协议。

## 部署验收

1. 专用测试 PostgreSQL：全量 `VMP_TEST_DATABASE_URL=... go test -race -count=1 ./...`，不能把未配置 DB 的跳过当通过。
2. Agent：`go test -race -count=1 ./...`、`go vet ./...`，远程下载/路径/中断/ARP/Guest Agent/回滚测试；真实硬件另做只读预检和受控最小测试 VM，不以模拟执行器宣称真实 KVM 全量通过。
3. 前端：Node 回归与真实浏览器，分页超过一页、导航期间慢请求、弹窗与凭据确认、LDAP 来源切换、普通用户越权必须覆盖。
4. 构建后在隔离数据库启动发布镜像验证迁移到 020、健康、登录和列表 API，再运行镜像自带 Web 与安全头验证。
5. 远程来源默认限制、缺镜像/桥/新协议拒绝调度、旧运行令牌拒绝、首次改密与本地应急管理员保留、安全 Cookie/CSRF/CSP 必须保留。

## 不承诺的能力

本版不是完整企业审批引擎，不含多级审批/会签、按部门配额、跨平台迁移、磁盘快照备份、镜像私有签名验签系统、Object Storage SDK 身份托管或 SLA 故障迁移。远程 OSS 使用受限 HTTP(S) 下载地址，租期通知不是磁盘备份；管理员仍必须规划资源、IPAM、镜像来源和安全备份。
