# 后端架构设计

## 职责边界

控制面保存期望状态、执行调度和租期规则，Agent 负责宿主机现场状态与虚拟化操作。两者通过稳定 JSON 协议通信，不共享 Go 内部包，因此可独立发版。

## 核心流程

1. 用户提交固定规格、镜像、网络和租期。
2. 数据库事务内锁定资源，选择可调度宿主机并预留 IP。
3. 生成一次性密码，由 `pgcrypto` 生成摘要，再构建幂等 `CREATE_INSTANCE` 任务。
4. Agent 拉取并回传执行结果。
5. 控制面更新实例、IP 和任务状态。
6. 用户可下发开机、关机、重启、密码重置和续期操作，所有虚拟化写操作仍由 Agent 执行。
7. 调和器每 15 秒检查租期：到期先关机，保留 7 天后再删除，删除成功才释放资源并清除实例相关控制面记录。
8. 自动回收任务连续失败达到上限后停止重新生成，避免对故障宿主机无限重试。

## 安全边界

- 浏览器通过 HttpOnly、SameSite=Strict Cookie 建立服务端会话，客户端传入的用户名不会作为身份依据。
- 管理员拥有平台管理权限；普通用户只能申请虚拟机并访问申请人为自己的实例。
- 平台账号与 LDAP 账号使用独立登录类型，后端同时校验用户来源。
- 本地用户密码保存 bcrypt 哈希；LDAP 用户登录时直接绑定目录服务，平台不保存用户目录密码。
- LDAP 服务账号密码使用 AES-GCM 加密，密钥与数据库分离保存。
- `kvm-readonly` 主机状态始终为隔离或降级，不会被调度。
- Agent 注册令牌和运行令牌分离。
- 调度、IP 预留、实例和任务创建使用串行化事务。
- 存量域只进入发现表，不自动变成平台托管实例。
- 新注册的 KVM 宿主机无论是只读还是写模式，初始状态均为 `CORDONED`，必须手工恢复调度。
- 明文初始密码不持久化，不写入任务或审计日志。
- 重置实例密码时同样只在当前响应返回明文，任务仅携带 crypt 摘要，并由 QEMU Guest Agent 在虚机内应用。
- 宿主机调度容量取 Agent 安全上限与管理员配额的较小值，Web 无法绕过 Agent 上限。
- 网络和唯一有效的 IP 起止范围由管理员在同一个配置中显式定义；修改范围只移除旧的空闲地址，范围外存在占用地址时拒绝修改。Agent 在任何虚拟化写操作前复检 IP 是否已被占用。
- 远程镜像在校验和同步完成前不允许启用。
