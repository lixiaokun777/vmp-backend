# 登录防暴力破解

后端 0.4.4 起默认启用，无需前端或 Agent 升级。016 迁移由控制面启动自动执行。

## 规则

- 每个来源 IP 每分钟最多 30 次登录请求，包括无效 JSON、不同用户名和不同登录来源；成功登录不会重置 IP 总量。
- 每个登录来源 + 忽略大小写、去除首尾空格的账号，在 15 分钟窗口最多预占 5 次尝试。第 6 次返回 HTTP 429，中文提示和 Retry-After 等待秒数。
- 密码正确且会话创建成功后清理对应账号计数，但不覆盖随后产生的并发尝试。错误密码、禁用用户、未知用户及 LDAP 校验失败都消耗次数；本地和 LDAP 分别计数。
- 计数先于密码计算原子写入 PostgreSQL，因此并发请求、重启和多副本不能绕过。认证内部错误也保守地消耗一次。
- 超限请求不延长原有窗口。到期后自动恢复，不永久锁定用户。无需管理员解锁。
- 登录保护存储故障返回 503，不降级为无限次密码校验。请求体最多 8 KiB，账号最多 256 字节，密码最多 1024 字节，服务端登录流程有 15 秒上下文期限。
- 正常密码失败继续写入登录审计；被限流的后续请求不逐条写入，以免攻击者刷爆审计表。计数键只保存 SHA-256 摘要，不保存密码。
- 该机制限制撞库和爆破速度，不代替强密码、HTTPS、网络入口防护或未来 MFA。攻击者仍可能造成短暂冷却；公网部署应叠加网关限流/访问控制。

## 可信代理

默认 TRUSTED_PROXY_CIDRS 为空，仅按直接连接地址限流，忽略 X-Forwarded-For。登录会话与审计使用同一来源地址算法。

经 Nginx 代理访问时，未配置可信代理会把所有用户按代理 IP 共享每分钟 30 次限制。生产上线必须按实际网络拓扑填写精确代理 IP 或专用网段，例如：

```dotenv
TRUSTED_PROXY_CIDRS=172.22.0.3/32
```

此地址仅为示例，不可直接照抄。Docker 中可查看实际 web 容器地址：

```bash
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' vmlease-web-1
```

写入 .env 后重建控制面容器（不会重建数据库）：

```bash
docker compose --env-file .env -f deployments/compose/compose.yaml up -d --no-deps --force-recreate control-plane
```

容器地址改变后需同步修改。可以给 web 配置固定 IP，或使用只包含受控容器的专用代理网段。不要填写整个内网、全部网络、客户端网段；禁止 0.0.0.0/0 和 ::/0。

仓库 Nginx 作为直接入口时覆盖客户端转发头为 $remote_addr。多级代理必须逐级建立信任，并在入口清洗客户端伪造头；后端从右往左剥离可信节点，遇到第一个非可信地址即停止。只信任 X-Forwarded-For，不使用客户端提供的 X-Real-IP。后端端口不要暴露公网。

## 验证与排障

请使用专门测试用户或不存在的测试账号，不要对真实 admin 连续试错导致管理员冷却。

- 连续输入错误密码 5 次应返回 401，第 6 次返回 429。
- 改变大小写、首尾空格或伪造 X-Forwarded-For 不应绕过。
- 冷却结束应可重新登录；正常登录清除自身账号计数。
- 若多个用户同时被限流，检查代理信任及共享出口情况。
- 503 时检查数据库及迁移日志，不要通过删除生产计数或关闭校验来绕过。

go test ./... 默认运行来源 IP 单元测试。设置 VMP_TEST_DATABASE_URL 后，go test ./internal/httpapi -run TestLoginProtectionDatabase -v 使用随机独立 schema 验证并发、重启共享、窗口恢复、成功清理及故障关闭。需要建 schema 权限与 pgcrypto 扩展；不会修改真实用户、会话、实例或登录计数。
