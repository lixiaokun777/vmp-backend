# 累计续期审批（0.8.1）

续期不再仅判断“本次是否超过168小时”。最终到期时间超过实例首次创建时间加168小时，即使只续1小时也必须审批。恰好168小时仍可免审批；单次超过168小时也始终审批。

创建时间作为不可重置的基准，既有到期时间不追溯缩短。管理员批准只授权这一次延期，后续延长继续检查。待审批时不修改实例到期时间，不保留超出原租期的资源；原有到期、保留期逻辑继续执行。

续期判断、重复审批检查和写入在同一实例行锁事务下执行，防止并发短续期绕过边界。有待处理续期审批时不能继续修改到期时间。自动续期遇到累计上限或待处理审批时暂停，保留失败原因、原到期时间和已执行次数，用户需要手动提交或处理审批，不自动批量创建审批单。

新续期审批保存原到期时间、提交时基准与目标到期时间。批准时以该基准加管理员调整后的小时数计算，不因审批等待而从新的当前时间重新累加。实例到期时间已被其他操作改变或批准目标已过期时拒绝执行，需重新申请。旧版待审批单兼容旧负载，仍只授权当次执行；平台硬性未来/连续租期上限仍约束批准操作。

“改成短租期重提”也经过累计判断，必要时重新审批，不能绕过规则。审批列表展示申请目标到期，批准成功后展示实际到期时间。

本次仅改变续期与自动续期；创建和保留期恢复维持既有规则（单次超过7天审批、恢复次数受限）。配套前后端镜像均为0.8.1，无新数据库迁移、Agent配置或环境变量；已有Agent 0.7.3不必因本次修复替换。现有发布标签不覆盖，发布不自动升级服务器。操作见 [0.8.1升级说明](0.8.1发布与升级.md)。

本地验证使用项目要求的 Go 1.26 与专用 PostgreSQL 16：全量 `go test -race -count=1 ./...`、`go vet ./...` 通过，新增边界、并发、批准调整、自动续期与过时审批用例。前端71项测试通过。数据库测试创建独立schema和模拟任务，不连接业务Agent、不修改现网实例；该结果不代表已部署。
