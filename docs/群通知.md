# 群机器人租期与平台事件通知

后端 `0.4.3`、前端 `0.4.2` 开始支持 WPS / WOA 群机器人通知。管理员在“平台管理 → 通知设置”配置，不需要修改 Agent。普通用户不能读取或修改通知配置、发送记录。

0.5.1 增加审批提交、审批/交付失败、宿主离线及恢复三组独立开关。启用总开关后才生效；不把每次 Agent 心跳当通知。配套版本的完整升级仍要求更新 Agent，以提供新调度与就绪协议。

## 配置步骤

1. 在所有平台用户所在的群聊中创建机器人，复制群消息发送 Webhook 地址。
2. 确保控制面服务器能通过 HTTPS 访问机器人。支持 `https://xz.wps.cn/api/v1/webhook/send?key=...` 以及自建域名、非默认端口和 `/woa/api/v1/webhook/send` 路径。
3. 在通知设置中填写机器人地址和群成员能访问的平台地址。机器人启用了签名校验时，填写它的 `secret_key`。
4. 保存后发送一条测试消息，在群中确认收到了“群通知测试”。
5. 勾选“启用自动群通知”并保存。默认关闭，未配置机器人时不会尝试发送。

机器人地址里的 key 与签名密钥使用 `SETTINGS_ENCRYPTION_KEY` 加密存入数据库，API 只返回已配置标志和打码地址。输入框留空保持原值，勾选清除复选框可清除凭据。迁移时必须保留并备份原配置加密密钥。

关键词限制应允许“北斗云台”，所有消息都包含该前缀；IP 白名单填写控制面的实际出口 IP。签名采用文档规定的请求体 MD5、Content-Type、GMT Date 和 SHA-1，双方密钥须一致、服务器时间应同步。TLS 校验开启，不支持忽略证书错误或跨地址重定向。

## 提醒规则

后端 0.4.5 起默认使用 Markdown（msgtype=markdown，markdown.text），无需重新保存配置或升级前端 / Agent。消息包含标题、批次数量、逐台实例分区、加粗字段和可点击的平台入口；临近到期使用橙色，剩余不超过 1 小时与最终删除警告使用红色。使用机器人文档列出的 Markdown 子集，不依赖表格、交互回调或额外卡片组件。实际颜色、@ 与字体效果由群客户端决定。

同一批次的续期与保留期处理提示只在底部说明一次。名称、账号等外部字段转换格式字符，防止生成恶意 Markdown 链接或 @ 所有人。签名 MD5 与 SHA-1 均按实际 Markdown JSON 消息体计算。

| 场景 | 默认时机 | 内容 |
| --- | --- | --- |
| 租期即将到期 | 提前 24 小时、1 小时 | 实例名称、使用人、到期时间、剩余时间、续期入口 |
| 已进入保留期 | 确认实例处于保留期后 | 原磁盘和 IP 仍保留、最终删除时间、恢复入口 |
| 保留期即将结束 | 结束前 24 小时 | 提醒恢复或备份数据，明确磁盘即将删除 |
| 新待审批 | 启用后新建且未超时 | 审批单号、申请人、租期、待审批入口 |
| 审批或交付失败 | 启用后且最近 24 小时 | 资源/任务标识、中文排查入口；不发送原始敏感错误 |
| 宿主异常与恢复 | 超过 120 秒未心跳或状态转离线，恢复时再发一次 | 宿主名称、影响提示、管理员排查入口 |

提前提醒可配置 1–168 小时的 1 至 5 个不重复整数。每分钟检查一次，通常可能晚约一分钟，积压和重试会更晚。短租期或刚开启通知时仅选择当前最紧急的阶段，不补发错过的提前提醒。仍在关机过程中的实例不会被误报为已进入保留期。

启用后会提醒当前即将到期的存量实例；进入保留期提醒仅覆盖启用后状态更新的实例，临近保留期结束的存量实例仍可收到最后提醒。

每轮最多合并 10 台实例，按长度缩小批次，最多发送一条自动消息/分钟，正文不超过 4500 个 Unicode 字符。手工测试至少间隔 3 秒，与自动发送共享锁和发送时间，合计不超过 20 条/分钟。不使用 @ 所有人。

按邮箱 @ 使用人时，使用用户管理中的邮箱生成 `<at email="...">`。LDAP 用户采用同步邮箱，本地用户采用管理员填写的邮箱。邮箱必须与群成员 WPS / WOA 账号匹配，匹配结果由消息服务决定；平台无法确认 @ 是否匹配成功，没有邮箱时仍显示名称和用户名。

群消息不包含登录密码、SSH 凭据、VNC 票据、机器人 key 或实例 IP。时间统一使用北京时间。超过 7 天的续期仍需审批，通知不代表自动续期。已恢复过一次的实例不再享受第二次保留期。

## 去重、重试和记录

事件以“实例 ID + 提醒阶段 + 目标时间”为唯一键，正常情况下同一租期同一阶段仅发送一次。续期、恢复按新时间计时；释放、删除、租期变化后取消旧的未发送提醒，已发送记录保留。配置修改与测试写入平台审计。

网络、HTTP、机器人业务错误均视为失败，最多尝试 5 次。第 1–4 次失败后等待 1、5、15、30 分钟再尝试；达到上限标为失败。重试前核对实例状态，过时消息取消。发送失败不会阻止资源回收或审批。

管理页支持全部、等待/重试、成功、失败、已取消筛选，每页 20 条，详情包含正文、错误原因、尝试次数和发送时间。只刷新记录不会重置正在填写的配置。

多副本使用 PostgreSQL advisory lock 串行调度，无外部队列依赖。HTTP 发送与数据库写入无法构成原子事务：若机器人已接收消息但响应丢失，或控制面在记录成功前崩溃，重试可能产生重复消息，不承诺端到端严格一次投递。

平台事件与租期事件共享发送锁及每分钟一条自动消息额度。平台事件按事件键跨重启去重并持久化重试；关闭对应开关会取消未发送事件。宿主只在离线/恢复边沿生成消息，初次健康状态不群发。若平台停机超过 24 小时，不补发更早的交付失败，仍可在任务和审计查询历史根因。

## 升级与验证

后端自动执行 `015_group_notifications.sql` 创建配置及事件表。旧版升级默认不向群发送消息，Agent 无需更新。

```bash
go test ./...
go vet ./...
```

设置 `VMP_TEST_DATABASE_URL` 后可运行 `go test ./internal/httpapi -run TestNotification -v` 做数据库集成验证。测试使用唯一随机 schema，结束后仅删除该测试 schema，需要建 schema 权限。测试机器人是本地 HTTP 服务，不会向真实群发送消息，也不修改真实虚拟机。
