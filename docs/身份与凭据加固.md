# 身份与凭据加固及升级

本次协议升级必须配套升级控制面与 Agent。不要只替换后端后继续运行旧 Agent；不要未验收就在现有 KVM 宿主直接切换。Agent 自身与现有虚拟机无须重建，凭据迁移只影响平台通信。

## 1. 取消全局运行令牌

- 控制面只保留首次纳管的 `AGENT_BOOTSTRAP_TOKEN`，必须为至少 32 字节的独立随机 ASCII 值，不得为空、使用开发默认值/公开示例值或重复字符弱值。建议 `openssl rand -hex 32`，不要把输出提交到仓库。
- 后端旧 `AGENT_RUNTIME_TOKEN` 不参与任何认证。若旧环境仍提供该变量，启动只显示不含值的弃用警告；请从后端环境移除。
- 首次新宿主注册后由控制面生成 32 字节独立随机运行令牌，响应只返回一次；数据库只存 SHA-256，Agent 在自己状态目录的 `credentials.json` 保存，文件 0600，目录 0700。
- 已纳管名称只能携带自己的有效运行令牌续注册。无凭据、吊销、跨宿主、拿 bootstrap 代替运行凭据均拒绝，不能靠改名称/宿主 ID 接管已有身份。
- 管理员可单独轮换/吊销某一宿主；不会更换所有 Agent，也不会清空/重建原有虚拟机。
- 宿主运行凭据目前不自动到期，组织需按自己的周期由管理员轮换；不要把它和五分钟一次性控制台票据或任务执行租约混为一谈。

`018_identity_hardening.sql` 不把旧全局值导入任何宿主身份。现有无独立凭据宿主会暂停新增调度（CORDONED），明确避免旧配置继续参与执行。

## 2. 已有环境升级顺序

1. 备份数据库、控制面配置、Agent 配置和 Agent 状态目录；安排受控窗口，不修改现有 libvirt 域或虚拟机磁盘。
2. 暂停新增申请/审批调度，确认在途任务，停止旧 Agent 的任务领取；不要让新旧 Agent 共用状态目录并行运行。
3. 部署新控制面并等待自动迁移成功。控制面设置新随机 `AGENT_BOOTSTRAP_TOKEN`，移除后端全局 `AGENT_RUNTIME_TOKEN`。
4. 管理员使用有效登录会话对每台已有宿主分别调用 `POST /api/v1/hosts/{id}/credentials/rotate`。保存本次返回的 `host_id` 与 `runtime_token` 到该宿主自己的受限配置，不在终端历史、文档、群聊或日志中保存。旧令牌不可用，切勿将同一新值复用给另一台宿主。
5. 升级匹配版本的 Agent，通过 `AGENT_HOST_ID` 和 `AGENT_RUNTIME_TOKEN` 一次性导入该宿主身份，或按 Agent 文档提供专属 `credentials.json`。Agent 验证原 ID、完成原子保存后可移除一次性导入的环境令牌；普通重启从本机凭据文件读取。
6. 确认续注册成功、心跳/任务领取正常，原域清单和非平台虚拟机没有变化；完成受控验证后管理员手动恢复宿主调度。未见凭据签发后的新心跳，恢复 ACTIVE 会被拒绝。
7. 对下一台宿主重复签发/导入/验证，不做全池一次性盲切换。控制台核销也必须使用所在宿主的独立运行身份。

注册响应成功但 Agent 尚未保存凭据就发生掉电时，不允许 bootstrap 再次接管该名称；管理员重新签发后导入即可。该失败关闭行为是有意设计。

控制面 JSON 请求体总量上限为 8 MiB；登录限 8 KiB，首次注册限 16 KiB，任务续租限 1 KiB。HTTP 入口同时限制请求读取、响应写入、空闲连接时间和请求头大小；大规模宿主清单应在容量验收中确认，不关闭这些边界来解决异常请求。

## 3. 轮换、吊销与丢失处理

- `POST /api/v1/hosts/{id}/credentials/rotate`：签发新值，旧值立即不再接受新请求；宿主暂停新增调度。把新值只更新到目标 Agent 后确认心跳，再恢复调度。正在执行的任务使用新的宿主身份上报结果，同时仍需任务 `claim_token`，不能更改领取身份。
- `POST /api/v1/hosts/{id}/credentials/revoke`：失窃或撤销纳管时立即拒绝后续 Agent 认证并暂停新增调度，已有虚拟机不会被停止或删除。
- 凭据文件丢失：联系管理员单宿主 rotate，不重新注册新宿主名，不修改 host ID，不使用旧全局令牌绕过。
- 撤销/轮换不能撤回已经在此前合法授权并进入执行的请求；应结合停止相关 Agent、主机访问控制和审计处置。API 令牌必须经 HTTPS 传输，日志不得打印请求头/完整凭据。
- 回滚到不支持独立身份的旧控制面可能重新扩大共享身份风险，不能把旧全局令牌重新开启作为临时修复。数据库不自动逆迁移，回滚需专门审查兼容协议。

使用管理员 Cookie 自行调用签发/吊销、LDAP 同步或其他写接口时，必须携带 `X-VMP-Request: 1`，否则返回 403“请求安全校验失败，请从平台页面重新操作”。平台前端自动附加；Agent 使用独立 Bearer 身份，不使用浏览器 Cookie，也无需该安全头。不得开启宽泛 CORS 来绕过此防护。

## 4. LDAP 平台停用与目录状态

用户 `enabled` 是管理员控制的停用状态，`ldap_directory_present` 只表达成功全量同步结果中的目录存在性。目录用户重新出现不会把管理员停用的账号启用。用户登录和已有会话都要求平台启用且目录存在。

历史版本把两者混在同一 enabled 字段中；升级后既有 `enabled=false` 会保守地继续停用，不能自动判断过去是管理员操作还是目录同步。需要管理员确认后明确启用，不静默恢复历史停用账号。

登录先使用只读查询账号（或明确允许查询的匿名目录）按配置的 Base DN 与登录过滤器查询，要求唯一 DN 且用户名属性等于规范账号，再绑定用户密码。用户换 OU 后使用本次查询的 DN；零/多结果、组限制不匹配、属性不一致均拒绝。登录过滤器必须包含 `%s`；用户输入经 LDAP 转义，语法无效配置拒绝保存。

同步按 500 条分页，全部查询成功后事务性写入；任何页失败不提交局部同步。网络连接、LDAP 请求有期限且上层上下文取消主动关闭连接。LDAP 查询请求单次最多等待 8 秒，登录总流程 15 秒，管理员连接测试 25 秒、同步 45 秒；大量目录需按规模评估窗口，不能用无期限等待掩盖目录问题。

配置与登录的安全判断必须以服务端为准；用户界面需区别“平台停用”和“目录不可用”。建议长期保留受控本地应急管理员，不仅依赖同一企业目录。

## 5. 验证

本机测试使用假 LDAP，不连接真实企业目录：

```bash
go test ./internal/httpapi -run 'TestIdentitySecretAndIdentifierPolicy|TestLDAPLoginFilterAndUniqueDN|TestLDAPRequestContextDeadline' -v
```

设置专用测试数据库 `VMP_TEST_DATABASE_URL` 后可运行数据库集成测试。测试会创建随机 `identity_test_*` schema，执行迁移并清理自身 schema，不修改实际用户或宿主：

```bash
go test ./internal/httpapi -run 'TestScopedAgentIdentityDatabase|TestLDAPSyncPreservesPlatformDisableDatabase' -v
```

验收必须覆盖：两宿主凭据不同；A 凭据请求 B 心跳/任务/结果/续租/控制台核销返回 401；bootstrap 不可接管已有名；管理员轮换后旧值失效；吊销后新值失效；普通用户签发返回 403；已停用 LDAP 用户同步后仍停用；组过滤规则不匹配拒绝；目录无响应时超时退出。
