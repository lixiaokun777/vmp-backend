# 部署运维

新环境请先阅读 [VMP 完整部署指南](部署指南.md)。本文保留发布检查、回收策略和迁移注意事项，不能替代首次安装手册。

## 上线前检查

1. 替换数据库密码和至少32字节随机 Agent 引导令牌；运行凭据由控制面按宿主独立签发，后端全局运行令牌已弃用。旧环境必须执行 [身份与凭据加固升级步骤](身份与凭据加固.md)，不得只替换后端。
2. 备份数据库并在受控窗口执行新迁移。
3. 验证 `/api/v1/health`、日志和数据库连接池。
4. 确认新增宿主机保持 `CORDONED`，完成人工验收后再放开调度。
5. 执行 `004_agent_provisioning_contract.sql`，确认每个启用镜像的 `file_name` 与 Agent `KVM_IMAGE_ROOT` 下的实际文件一致。
6. 执行 `005_reconcile_node3_image_inventory.sql`。当前只启用已验证存在的 Ubuntu 22.04；上传并校验 Ubuntu 24.04 镜像后才能重新启用。
7. 执行 `006_instance_lifecycle.sql`，确认控制面每 15 秒扫描到期和保留期实例。
8. 执行 `007_admin_resource_management.sql`，确认宿主机 Agent 上限、平台配额和镜像来源字段已完成回填。
9. 执行 `008_task_success_cleanup.sql`，确认已成功任务不再显示历史重试错误。
10. 执行 `009_auth_rbac.sql`，设置一次性的 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD` 创建首个管理员；创建成功后应从环境中移除初始密码。
11. 执行 `010_ldap_settings.sql`，配置至少 32 位随机 `SETTINGS_ENCRYPTION_KEY`，并将密钥单独备份。丢失或更换密钥后，已保存的 LDAP 绑定密码无法解密。
12. 执行 `011_audit_console.sql`，配置至少 32 位随机 `CONSOLE_SIGNING_KEY`，并确认所有 Agent 使用同一密钥。

LDAP 配置由管理员在用户管理页面维护，环境变量仅作为未保存页面配置时的兼容回退。生产环境应使用 `ldaps://` 或 StartTLS，服务账号只授予用户目录读取权限。页面和 API 不回显已保存的绑定密码。

到期回收不会立即删除数据。控制面先下发优雅关机任务，保留 7 天后再下发删除任务。关机失败不会强制断电，需要运维人员检查任务错误。

同一自动回收任务连续失败 3 次后标记为 `FAILED`，调和器不会立即生成新任务。排除宿主机或域状态故障后，由用户重新提交操作，或由运维人员处理失败任务。

## 回滚原则

应用回滚使用上一个镜像版本。数据库结构不自动逆向回滚；需在发布前准备兼容方案或单独的修复迁移。
## 控制台配置

控制面通过 `CONSOLE_SIGNING_KEY` 签发 VNC/串口短时票据。该值至少 32 个字符，必须与所有 Agent 一致，且不得提交真实生产密钥。使用 HTTPS 发布平台时，Agent 上报的地址必须使用 `wss://`，否则浏览器会拒绝混合内容。

## 迁移

已有数据库升级由控制面自动按编号执行尚未应用的迁移，并校验历史摘要。身份协议升级包含 `018_identity_hardening.sql`；先备份并安排受控升级窗口，现有宿主需分别签发/导入新凭据。不要手工重跑历史迁移或重新执行 `001_init.sql`。

## 审计保留

强制删除或保留期回收会清理实例、申请与任务，但不删除 `audit_logs`。备份、存档和最终保留周期由组织合规策略决定，不应在业务删除流程中级联清理。
